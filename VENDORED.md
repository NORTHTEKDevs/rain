## Provenance hash protocol

When vendoring, record in this file:
- Source file absolute path
- Source git ref (commit SHA) at copy time
- SHA-256 hash of the copied file content
- Destination path in this repo
- Date copied
- Adapter notes (e.g., "ported from 4K FHRR to 10K bipolar")

Example entry format (one block per vendored file):

```
## rck/relational.py → rain/core/relational.py
- Source: ~/projects/active/rck/rck/relational.py
- Source SHA: <commit>
- File SHA-256: <hash>
- Vendored: <date>
- Adapter: Plate HRR primitives adapted from D=4096 complex-valued FHRR
  to D=10000 bipolar Kanerva. Multiplicative binding semantics preserved.
- Tests: see tests/core/test_relational.py
```

## Adapter responsibilities

1. **Update header on every vendored file.** The patent-pending header is
   re-stamped with current date and the RAIN copyright line. Original-source
   copyright is preserved if the original repo had a different attribution.
2. **Adapt bind-space.** RCK files using 4K complex FHRR must be ported to
   10K bipolar before integration.
3. **Strip imports** to anything not in RAIN's component set. (e.g., RCK
   `server.py` imports stdlib http — if a vendored file imports it, that's
   a sign the file should not be vendored.)
4. **Write integration tests** for every vendored module that pin its
   behavior in the RAIN context.
5. **Log the vendoring** by appending an entry to this file's "Provenance
   log" section below.
